# 支援範圍與驗證

本分支是新版工作台的第一個整合版本。工具不直接執行資料庫修改；產生草稿不代表已通過真實 SQL Server 部署驗證。

## 功能支援矩陣

| 項目 | 已實作 | 邊界與限制 |
|---|---|---|
| Git 式檢視 | 左右／合併、紅綠行、字詞標示、對齊行號、同步捲動、相同區塊摺疊、上下差異導覽 | 文字 Diff，不是 SQL 語意等價分析；小視窗手動切合併檢視 |
| 資料表 | 欄位、主鍵、索引；以物件身分配對，索引差異不逐欄重複 | 不涵蓋分割、壓縮、filegroup 等儲存配置 |
| FK／CHECK | 定義與 enabled／trusted 狀態，可選範圍 | 不執行來源／快照中的任意 CHECK 表達式 |
| View／Function／SP | SQL 定義、物件類型、SET 選項、部分綁定設定 | CLR／加密／不可讀取定義標示無法比對，不判定一致 |
| Trigger | 資料表／View 的 DML Trigger | 不涵蓋資料庫或伺服器 DDL Trigger；特殊相依場景仍需整合測試 |
| 目標額外物件 | 保留、獨立狀態、不自動 DROP | 目標擴充不是需要刪除的部署指令 |
| 變更計畫 | 可解析相依排序、風險分類、阻擋項目、SQL 草稿 | 相依 metadata 並非完整部署圖；動態 SQL、外部參照需人工確認 |
| 唯讀資料預檢 | NULL、長度、部分轉型／精度、未篩選唯一索引重複鍵、FK 孤兒資料 | 可能掃描表；CHECK、filtered index 表達式、轉型後唯一性與資源需求需人工檢查 |
| 資料匯出 | 所有可讀來源表、欄位選取、唯一鍵排序、條件、筆數、完整時間精度 | 有上限的設定資料工具，不是大量資料搬移工具 |
| 資料補齊 | 指定來源鍵範圍的缺少／不同／相同；預設只補缺 | 不掃描目標獨有資料，不代表全表一致 |
| 選擇性 UPDATE | 使用讀取時選取欄位的二進位值做樂觀並發檢查 | 不是 rowversion；只保護選取欄位，不能盲目重試草稿 |
| 多目標 | 已驗證目標佇列、來源讀一次、目標逐一處理、失敗重試 | 不會同時對多個環境執行資料修正；連線只留在本次記憶體 |
| 報告與快照 | JSON／HTML／CSV、離線快照比對、標準快照對即時目標 | 快照包含定義，須可信且妥善保管；範圍不相容時不可推論缺少 |
| 環境與歷史 | 不含帳密的環境設定、最近 100 份歷史摘要 | 不自動保存完整 SQL 或資料；多程序同時修改環境設定尚未提供跨程序合併 |
| 新版命令列 | 共用新 GUI 引擎與設定；明確部分完成退出碼 | 舊 CLI 不加 --workbench，仍保持舊行為 |

## 安全邊界

本機連線測試、結構讀取、資料讀取及資料預檢只發出查詢，不會呼叫生成腳本的執行流程。資料條件值使用參數；物件識別字有引用／跳脫。任意 WHERE 片段不是功能的一部分。

匯入快照是外部輸入。程式驗證版本、必要欄位、重複鍵、部分型別範圍與檔案大小。CHECK／filtered index 的任意 SQL 表達式只作為定義資料，不在預檢中直接執行。完整 SQL 草稿仍可能包含標準定義，因此只應使用可信快照並人工檢閱。

SQL 草稿檢查目標伺服器／資料庫，拒絕既有交易，使用 XACT_ABORT 與 TRY/CATCH 交易防護。工具不執行草稿。保護不是部署保證：資料、相依性或環境在產生草稿後仍可能改變。

來源與目標不是同一個一致性快照。資料預檢會重新檢查目標 metadata 是否與基準相符，但這不能避免預檢後的 DDL／DML 改變。重新比對與人工審核仍必要。

HTML 報告做內容編碼；CSV 對可能被試算表當成公式的字首做防護。完整 SQL 與資料只在使用者明確選擇匯出時寫檔。

## 上限與效能取捨

Git 式預覽最多 20,000 行／2,000,000 字元；單行顯示超長內容會截短，複製仍保留完整原文。Diff 計算有矩陣與字詞預算，過大區塊改用簡化配對，畫面會提示；實際一致性判定不受預覽截斷影響。

資料工具每表最多 10,000 筆、最多 256 個選取欄位，单一大值上限 1 MiB，資料缓衝上限 16 MiB。超過時停止而不是輸出不完整 SQL。SQL 文字與視窗另有記憶體成本，這些數值不是整個程序記憶體的硬限制。

來源按唯一鍵取樣；目標以分批鍵集合配對，避免逐資料列的 N+1 往返。不代表零資料掃描：預檢 COUNT、轉型與約束檢查可能讀取全表。

主要資料型別支援以現有程式分支為準。CLR／空間／sql_variant／加密／generated 等不可靠寫入情況會拒絕。text／ntext／image／XML 的帶並發檢查 UPDATE 不支援，需改用經審核的專用流程。

## 已執行的驗證與未執行的驗證

GitHub Actions 的 Windows 工作負責：

1. 還原既有相依套件並以 Release 建置。
2. 執行 `--self-test` 的無資料庫回歸測試：Diff 重建與限制、比較狀態、相依計畫、防護腳本、日期精度、輸入驗證、編碼與檔案取消。
3. 執行 `--ui-smoke-test output/ui`，以合成資料開啟六個頁面，測試左右／合併模式，輸出 1440×900 與 1000×720 的 14 張畫面。

請以 PR 上最新 commit 的 Actions 結果為準。UI 截圖測試證明畫面可以建立與繪製，不等於完整互動、自動化點擊或所有 Windows DPI 設定都已驗證。

**目前沒有連接正式或測試 SQL Server，也沒有實際執行生成的 DDL／DML。** 以下仍是合併前／正式使用前的驗收工作，不應寫成已通過：

- 在獲准的測試資料庫驗證 SQL Server 版本、VIEW DEFINITION／SELECT 權限、加密設定與取消／逾時。
- 驗證複合主鍵、大小寫敏感定序、相同名稱不同 schema、UDT、特殊索引、計算欄位、schema-bound 模組與外鍵重建阻擋。
- 在隔離測試環境檢閱並執行 SQL 草稿，測試目標不符、轉型失敗、交易 rollback、既有資料衝突與並發 UPDATE 防護。
- 驗證大型 catalog／LOB 及 125%、150%、200% Windows 縮放的實際操作。

## 第一版已知 UI 邊界

小視窗的左右兩欄可能偏窄，請手動切「合併檢視」或拖曳分隔線。資料工具可收合設定區；空間不足的操作會放進工具列更多選項。

差異導覽剛建立後，直接第一次按「上一處」有初始索引邊界行為，可能不是最後一個差異群組。可先按一次「下一處」再導覽；不影響比較結果或 SQL 內容。這個小型 UI 修正尚未包含在本次分支中。

本版本沒有一鍵同步、任意 SQL 執行、雲端保存密碼或自動移除目標額外物件。
